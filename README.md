# speedtest.py

Консольный скрипт замеряет скорость скачивания по заданному URL. Делает несколько последовательных HTTP(S)-запросов, на каждом дочитывает тело ответа до конца и считает среднее время, суммарный объём и скорость. Использует только стандартную библиотеку Python.

## Требования

- Python 3.9+
- Внешние зависимости не нужны (`requirements.txt` отсутствует)

## Запуск

```bash
git clone https://github.com/Lleonsnow/url-speedtest.git
cd url-speedtest

python3 speedtest.py <url>
python3 speedtest.py https://proof.ovh.net/files/10Mb.dat
python3 speedtest.py https://proof.ovh.net/files/100Mb.dat -n 5 -t 120
```

На Windows вместо `python3` используйте `python`.

Пример вывода:

```
>> speedtest :: bandwidth probe
>> ------------------------------
[*] target      https://proof.ovh.net/files/10Mb.dat
[*] requests    10
[*] timeout     30 s

[+] 01/10  10.49 MB  3.340 s  25.11 Mbit/s
[+] 02/10  10.49 MB  3.421 s  24.52 Mbit/s
...
[+] 10/10  10.49 MB  3.099 s  27.07 Mbit/s

[=] successful  10/10
[=] downloaded  104.86 MB (104 857 600 bytes)
[=] avg time    3.634 s
[=] speed       23.08 Mbit/s (2.89 MB/s)
```

Пока идёт запрос, в его строке крутится спиннер `| / - \` и растёт счётчик скачанных мегабайт. Когда запрос завершается, строка заменяется итогом `[+]`, при ошибке — `[x]`.

Цвета и спиннер включаются, только если вывод идёт в терминал. При перенаправлении в файл или pipe, а также при заданной переменной окружения `NO_COLOR` печатается простой текст без escape-кодов.

Прогресс и итог печатаются в stdout, ошибки запросов — в stderr.

Параметры:

- `-n`, `--count` — число последовательных запросов (по умолчанию 10)
- `-t`, `--timeout` — тайм-аут в секундах (по умолчанию 30). Он действует на каждую сетевую операцию (соединение, чтение очередного блока), а не на весь запрос целиком

## Единицы и методика

Время одного запроса — интервал от момента перед `urlopen` до полного дочитывания тела. В него входят DNS, установка TCP-соединения, TLS (для HTTPS), ожидание ответа (TTFB) и скачивание тела.

Заголовок `Accept-Encoding: identity` просит сервер не сжимать ответ, поэтому подсчитанные байты совпадают с тем, что реально пришло по сети. Заголовки `Cache-Control: no-cache` и `Pragma: no-cache` просят промежуточные кэши не отдавать сохранённую копию.

Скорость считается как `total_bytes / total_time` по всем успешным запросам, а не как среднее индивидуальных скоростей. Так каждый запрос влияет на итог пропорционально своему времени и объёму: один короткий быстрый запрос не завышает результат. Неудачные запросы в расчёт не попадают.

Единицы десятичные (SI):

- 1 Мбит/с = 1 000 000 бит в секунду
- 1 МБ/с = 1 000 000 байт в секунду
- объём в отчёте: МБ с двумя знаками и сырое число байт

## Тестовые URL

- https://proof.ovh.net/files/10Mb.dat (~10 MiB, удобно для 10 запросов)
- https://proof.ovh.net/files/100Mb.dat (~100 MiB)
- https://cachefly.cachefly.net/100mb.test (~100 MiB)
- https://proof.ovh.net/files/1Gb.dat (~1 GiB, для длинного прогона)

## Коды выхода

| Код | Значение |
|-----|----------|
| 0 | хотя бы один запрос успешен |
| 1 | все запросы завершились ошибкой |
| 2 | неверные аргументы (в т.ч. URL без схемы `http`/`https`) |
